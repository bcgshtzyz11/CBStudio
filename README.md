# CBStudio · 台架剧本工作台

> 图形化的台架测试工作台：把「上下电时序 / CAN 断发 / 状态卡编排」做成可拖动的剧本，
> 边跑边抓 DUT 串口与 adb，出事时**自动保留现场**（日志 / CAN 统计 / 截图一张不落）。

面向本工程（S32K328 仪表控制器 + RK3576 SOC 台架）的日常联调与压测，不是通用 CAN 工具。

---

## 1. 快速开始

```bat
:: 真机（会驱动继电器 / 打开 CAN 设备 / 占用 DUT 串口）
run_studio.bat

:: 台架被别人占着时：全模拟，不碰任何硬件
run_studio.bat --sim

:: 只干跑继电器（其余真机）
run_studio.bat --dry-run

:: 不开浏览器 / 换端口 / 启动就连 CAN
run_studio.bat --no-browser --port 8800 --connect-can
```

启动后自动打开 `http://127.0.0.1:8777/`（端口被占会自动顺延，控制台会打印实际地址）。

**依赖**：工作台主进程用 64 位 Python（3.10+，`pip install -r requirements.txt` 装 `pyserial`）；
CAN 部分由 32 位 Python 3.8 子进程跑（ZLG SDK 只有 32 位 DLL），工作台会自动找解释器并拉起，
无需手工启动。`zlgcan` 驱动已随包放在 `sdk/zlgcan/`，不用 pip 安装；`openpyxl` 只在重新生成
报文清单时需要。

## 1.1 硬件自动识别

配置里留空即「自动」，不用手工填口/型号/路径：

| 项 | 配置 | 自动识别方式 |
|---|---|---|
| 继电器串口 | `relay.port = ""` | 枚举串口，优先 CH340（LCUS-4），跳过 DUT 调试口等占用口，逐个试开直到成功 |
| ZLG 设备型号 | `can.device_type = 0` | 依次试 USBCANFD 家族与经典盒子，第一个能打开的即当前设备 |
| 32 位解释器 | `can.python = ""` | 环境变量 `CBSTUDIO_PYTHON`/`CBSTUDIO_PY32` → `py -3.8-32` → 本机 `Python3*-32` / ZCANPRO 自带 `python38` → PATH 上的 `python`；拉起后按 hello 回报的位数筛掉 64 位 |
| ZLG SDK 目录 | `can.sdk_dir = ""` | 环境变量 `CBSTUDIO_SDK_DIR` → 随包 `sdk/zlgcan` → 默认目录 → 各盘符下含 `zlgcan.dll` 的 `zlgcan*` 目录 |
| 报文清单 | `can.manifest = "can_matrix_manifest.json"` | 相对路径按工作台目录解析，从任何目录启动都能找到；缺失时报出解析后的绝对路径 |
| DUT 调试串口 | `probes.serial.port = ""` | 枚举串口，优先 Prolific/FTDI/CP210x（`067B`/`0403`/`10C4`），跳过继电器口（含继电器自动识别的首选口），逐个按波特率试开 |
| adb 路径 | `probes.adb.exe = ""` | PATH → 随包 `platform-tools/` → Android SDK（`ANDROID_HOME` / `%LOCALAPPDATA%\Android\Sdk`）→ 常见安装位置 |

继电器口与 DUT 口互相排除，不会抢同一个口。识别结果写进日志与状态栏，例如：

```
自动识别 DUT 串口: COM4（自动识别 USB-UART(067B:2303) Prolific USB-to-Serial Comm Port）
串口已打开 COM4 @460800
继电器串口已打开 COM5 @9600
已连接 USBCANFD-200U
```

想固定住就在设置里把对应项填死，填了就按配置走、不再自动。设置页的串口输入框带
下拉（列出本机串口 + 描述），继电器串口/波特率/干跑保存即重连，不用重启。

## 2. 界面速览

```
┌───────────────────────────────────────────────────────────────────────────┐
│ 顶栏：运行状态 · 第几轮 · 当前状态 · 计时 · 运行/暂停/停止/保留现场/设置      │
├──────────────┬──────────────────────────────────────────┬─────────────────┤
│ 通道（左）    │ 剧本时间线（中）                          │ 日志/事故/监看   │
│ 继电器/ CAN   │ 状态卡可拖动排序，点开编辑                │（右）           │
│ 上下电预设    │                                          │                 │
│ 采集：串口    │                                          │                 │
│ adb / CAN    │                                          │                 │
│ CAN 报文统计  │                                          │                 │
└──────────────┴──────────────────────────────────────────┴─────────────────┘
```

- **通道**：一键给电/断电。左侧开关点一下就是一次真实动作；继电器没有回读，
  界面上的 ON/OFF 是"推定值"。
- **剧本**：中间一列状态卡。`⠿` 拖动排序，单击卡片打开编辑器，`Alt+↑/↓` 移动，
  `＋添加状态` 追加。顶部改剧本名 / 循环次数（`0` = 无限）/ 轮间隔 / CAN 模式。
- **日志**：实时显示串口与工作台事件，支持级别筛选、文本/正则过滤、暂停、导出 CSV。
- **事故**：每次触发的现场一条记录，展开可看落盘文件，一键打开目录。
- **监看**：全局判定规则（正则命中 / 静默 / CAN 超时 / SOC 掉线 / 日志停更），
  命中即抓现场，可选择是否顺手停剧本。

快捷键：`Space` 运行/暂停 · `Esc` 停止 · `F` 保留现场 · `Ctrl+S` 保存剧本。

## 3. 核心概念

### 3.1 状态卡（State）

一张卡 = 一个台架状态。字段：

| 字段 | 说明 |
|---|---|
| 名称 | 卡片标题，只用于人读 |
| 保持 | 至少停在该状态多久（ms） |
| 通道 | 每个通道三种取值：**给电 / 断电 / 不动**。断电按 IG→ACC→主电，给电按主电→ACC→IG |
| 等待条件 | 保持之后继续等，直到满足或超时：SOC 在线 / 串口出现正则 / CAN 收到报文 / 日志在增长 |
| 断言 | 该状态窗口内必须成立：无 ERROR 日志 / 串口匹配（或不应出现）/ CAN 收到 N 帧 / SOC 在线（或离线） |
| 失败动作 | `继续` 记一笔接着跑 · `停止` 停下剧本 · `保全后停止` 先抓现场再停 |
| 进入动作 | 启动/停止 CAN 随机发送、打一个时间标记 |

### 3.2 剧本（Scenario）

有序状态卡 + 循环策略。`loops=0` 表示无限循环，每轮之间可设间隔。
`can.mode` 决定本轮是否启动 CAN 随机发送（`tx`）/ 只接收（`rx`）/ 不碰（`none`）。

**断电静默**（默认开）：剧本自己断电或断 IG 时，"掉线/静默"类监看自动降级，
恢复供电后重新计时——避免把**预期的**掉电判成事故。真出事的判定仍然照常。

**启动窗口**（`probes.boot_grace_ms`，默认 25s）：主电/IG 重新上电后，DUT 要跑
启动流程，这段时间内"没有 adb、没有日志"是正常的。窗口内不判掉线/静默/停更，
窗口过了还没起来才算事故——否则每个上下电剧本都会在上电那一刻自己判死自己。

### 3.3 抓取与判定

| 规则类型 | 用途 |
|---|---|
| `regex` | 串口行命中正则，窗口内达到次数即触发（如 `\[ERROR\]`） |
| `silence` | 串口在一段时间内没有（匹配某正则的）行，如 `SpiRx` 停更 |
| `can_timeout` | 某总线某 CAN ID 超过 N ms 没收到（丢帧/断线） |
| `adb_offline` | SOC 离线超过 N ms |
| `log_stall` | SOC 在线但 `mcu.log` 不再增长（活着但不干活） |

规则的**探针归属**决定它在什么上下文里才有意义：`serial` 按"主电在"门控、`adb`
和 `spi` 按"SOC 该在线"门控、`can` 常开。`SpiRx` 属于 `spi`——SOC 没电时本来就没有
这条日志，不能按主电判断（否则每次"仅主电"的电源测试都会误报 SPI 链路断）。

每条规则可单独开关、设级别、设冷却时间、是否保全现场、是否停剧本。
界面保存后立即生效，并写回 `config.json`。

### 3.4 现场保全（Incident）

规则命中或点「保留现场」时，在 `data/runs/<run>/incidents/<序号>_<时间>_<原因>/` 下留档：

```
incident.json      结构化现场：规则、状态卡、通道推定状态、探针/CAN 统计
README.md          人读摘要（什么规则、在哪个状态、当时通道什么状态）
serial_tail.log    出事前最后 256KB 串口日志（没有运行文件时退回内存尾部）
events_tail.jsonl  出事前最后 300 条工作台事件（含人工标记）
can_rx.json        各路 CAN 的每 ID 统计（计数 / 周期 / 最新数据）
can_rx.csv         逐帧接收记录（本次运行开了接收记录时）
adb/uptime.txt     SOC uptime（判断是否刚重启）
adb/mcu_log_tail.txt   DUT 侧 mcu.log 尾部
adb/screenshot.png    DUT 屏幕截图（DRM kmsgrab，见下）
```

**截图走 DRM framebuffer**：RK3576 仪表是 Buildroot，**没有 `screencap`**，
工具用 `kmsgrab --crtc <id>` 把 framebuffer 原样落到设备文件、`adb pull` 回来，
按 BGRA 解码成 PNG（自带编码器，不依赖 Pillow）。crtc id 从 `kmsgrab -h` 现读，
换板子不用改代码。Android 设备才走 `exec-out screencap` 兜底。

**持续故障只报一次**：静默 / 掉线 / CAN 超时 / 日志停更 四类是"持续状态"，
首次命中报一条并锁存，恢复正常后才重新武装——不会每过一个冷却就刷一条。

**默认不动电源**：出事后 DUT 保持原状，方便回看屏幕和日志；要恢复由人点
「整机上电 / 整机断电」。

### 3.5 电源状态机激励（待机 / 唤醒）

PowerMng 的状态不是"命令"切的，而是**总线上有什么帧**推出来的。所以状态卡支持一种
动作 `CAN 激励`，按状态启停激励，并配合 `等电源状态` / `电源状态 =` 做等待与断言：

| 激励 | 发什么 | 效果 |
|---|---|---|
| `任意帧` | 普通车身帧（ICAN+PCAN，如 `0x18FEF117`/`0x18FFE117`/`0x18FEF100`） | OFF→**待机(1)**；持续发 ⇒ 网络不静默，停在待机不会掉关机 |
| `唤醒帧` | 转向 `0x18FE4121`、双闪 `0x18FE4021`、BMS1 充电 `0x18FF21B1`、TBOX OTA `0x18FF11FC` | 待机→**监听(2)**，SOC 上电；持续发 ⇒ 监听窗口一直续期 |
| `指定帧` | 任意 id + 数据 + 周期 | 精确复现某条报文 |
| `静默` | 停掉全部激励 | 5s 无唤醒帧 → 待机(1)；网络静默 10s+15s → 关机(0) |

界面上有两个入口：

- **剧本**：状态卡的「进入动作」选 `CAN 激励（电源状态）`，选模式/总线/周期；
  配合「等待条件 = 电源状态到达」和「断言 = 电源状态」就能卡住每个状态迁移。
- **手动**：左下 CAN 面板有 `任意帧 / 唤醒帧 / 静默` 三个按钮，随时手动推电源状态。

电源状态来源：从 MCU 日志 `evt=I_PWRMNG_IO … state=N` 解析（0 关机 / 1 待机 /
2 监听 / 3 预开机 / 4 开机），左栏「电源状态」行实时显示，另记录迁移历史。

内置剧本 `电源状态机_待机与唤醒` 就是这条链路的完整用例：仅主电（关机）→ 任意帧
（待机）→ 停帧（回关机）→ 唤醒帧（监听，SOC 上电）→ 停唤醒帧（5s 回待机）→
ACC（预开机）→ IG（开机）→ 收尾断电。真机实测 11 张卡全绿、约 52s。

### 3.6 仪表画面与电压检测

- **抓屏**：左栏「抓屏」按钮随时抓一帧仪表画面，弹窗预览并显示统计；
  图片暂存 `data/screens/`，运行中同时复制一份到 `data/runs/<run>/screens/`。
  接口：`screen.capture`，图片地址 `/api/screen/<id>.png`。
- **画面断言** `{"type":"screen","min_ratio":0.15}`：状态结束时抓一帧，要求
  "非黑像素占比" ≥ 阈值——黑屏/没渲染会接近 0。
- **电压断言** `{"type":"voltage","min":18,"max":32}`：读 MCU 上报的蓄电池电压
  （`I_PWRMNG_IO` 的 `vbat`，也就是上行 `0x1C/0x9005` 的同一个 ADC 源），
  要求落在范围内；通过时日志会打 `电压 24.0V 在 18.0~32.0V 内`。

抓屏统计里：`bright_ratio` = 亮度 > 30 的像素占比（判断"画出来了没有"），
`text_ratio` = 亮度 > 180 的占比（文字/高亮），`mean_luma` 平均亮度。
真机实测一块正常运行的仪表：非黑 99.9%、高亮 1.5%、平均亮度 43。

### 3.7 手动发帧（唤醒帧 / 单帧模拟）

左下角 CAN 面板有一个「发帧」小工具：`ID + 数据(hex) + 次数`，按 100ms 周期发送，
**不受发送闸门与报文清单影响**。典型用途：

- 打 **转向唤醒帧** 把 OFF/STANDBY 的 DUT 拉进 LISTEN 并给 SOC 上电：

  ```
  0x18FE4121   00 50 00 00 00 00 00 00   次数 200   （左/右转向灯 = 1）
  ```

- 单独复现某条报文的某个取值（配合 HMI 日志看页面变化）。

真机验证：ACC/IG 全撤、SOC 已断电的情况下，发这帧 10 秒内 `I_POWERMNG_IO state=2`
（LISTEN）、SOC 上电、`adb` 枚举回来，`SpiRx` 恢复。

## 4. 硬件对应关系

| 资源 | 默认 | 说明 |
|---|---|---|
| 继电器 LCUS-4 | 自动识别（典型 `COM5` CH340） | CH1=主电、CH2=ACC、CH3=IG、CH4=备用；9600 8N1，无回读 |
| DUT 调试串口 | 自动识别（典型 `COM4` @460800 Prolific） | MCU 日志，工作台按行解析 |
| CAN | ZLG USBCANFD-200U，type 41（型号自动识别） | CH0=ICAN、CH1=PCAN，500 kbps，可在 CAN 配置弹窗里按通道改 |
| SOC | adb 自动探测（PATH / 随包 `platform-tools` / Android SDK） | 抓日志、抓屏 |
| 报文清单 | 随包 `can_matrix_manifest.json`（按工作台目录解析） | 由 `gen_manifest.py` 从矩阵 Excel 生成 |

这些都可在界面「设置」里改，保存到 `config.json`。

### 四条安全红线

1. **继电器 1 = 主电**：关它整机断电；只关 2/3 只是 SOC 掉电，MCU 仍带电。
2. **继电器没有回读**：任何"到底开没开"的判断只能靠 DUT 行为（adb / 串口 / 屏幕）。
3. **下电满 5 分钟才允许再上电**（压测规范）。剧本跑快速上下电时请确认是有意为之。
4. **台架被别人测试时，用 `--sim`**：不要连继电器 / CAN / 串口 / adb。
   把 `config.json` 里 `"simulate": true` 打开等价于每次都加 `--sim`。

## 5. 内置剧本

| 剧本 | 内容 |
|---|---|
| 整机上下电压测 | 全断 → 主电 → ACC → IG（等 SOC 在线）→ 稳定观察（**查电压 18~32V + 画面已画出**）→ 反序下电，默认无限循环 |
| 电源状态机_待机与唤醒 | 仅主电（关机）→ 任意帧（待机）→ 停帧（回关机）→ 唤醒帧（监听+SOC 上电）→ 停唤醒帧（回待机）→ ACC（预开机）→ IG（开机）→ 收尾断电 |
| 故障注入_IG 闪断 | 上电稳定后反复闪断 IG（200ms 断 / 800ms 通），20 轮 |
| CAN 发送中断注入 | 启随机发送 → 断 ICAN 5s → 恢复 → 断 PCAN 5s → 恢复，3 轮 |
| 冒烟_上电自检 | 最小流程：上电 → 等 SOC → 查 3s 无 ERROR → 留现场不下电 |

剧本是普通 JSON，放在 `scenarios/`，可以手工编辑、互相拷贝。

## 7. 扩展

### 加一路自定义通道

台架上还有别的可控设备（另一个继电器板、可编程电源……）时，在 `config.json`
的 `channels` 里加一项即可，剧本与界面自动出现：

```json
{
  "id": "psu",
  "label": "可编程电源",
  "kind": "custom",
  "on_cmd": "python set_psu.py --voltage 13.5",
  "off_cmd": "python set_psu.py --output off"
}
```

命令走 `cmd /c`，15 秒超时，输出进日志。返回值非 0 视为失败。

### 加一档构建/烧录动作

目前没有内置烧录步骤（避免误触发）。需要"跑 N 轮前重新烧录"时，可以把烧录命令
包装成 `custom` 通道，在剧本第一张卡里 `给电` 触发；或者直接写进 `on_cmd`。

## 8. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 打开页面提示"连不上工作台服务" | 控制台看是否启动失败；端口被占时地址会顺延，用控制台打印的地址 |
| 继电器卡显示"继电器未连接"，点上下电无效 | 串口打不开。看设置里的端口是否存在；**`Cannot configure port … PermissionError(13) 设备没有发挥作用` 是 CH340 驱动级故障（不是占用）**，重插继电器 USB 或在设备管理器里禁用/启用 CH340（需管理员）即可，改代码没用 |
| 继电器动作成功但 DUT 没反应 | 继电器没回读，先确认 CH1 是否真的吸合；再量 DUT 电源 |
| 串口显示"打开 COMx 失败" | 串口被串口助手/MobaXterm 占用；关掉占用程序后重启工作台 |
| CAN 显示"打开设备失败" | 设备被 ZCANPRO 或**上一位留下的发送脚本**占用（`Get-CimInstance Win32_Process -Filter "Name='python.exe'"` 看命令行）；用 `--sim` 先验证流程 |
| SOC 掉电后再也回不来 | 没有 ACC/IG 时，用「发帧」打 `0x18FE4121` 转向唤醒帧把 SOC 拉起来（见 3.5） |
| 剧本一上电就停 | 看「事故」里是哪条规则；把该规则关掉，或给该剧本打开"断电静默" |
| 事故目录里没有 adb/ | 模拟模式或 SOC 离线时不会抓 adb |
| 轮询/数据不动 | 检查右侧日志是否暂停；SSE 断开会自动重连，8 秒后退回 2 秒轮询 |

## 9. 版本

v1.0.9 — 修复「继电器识别不到」（DUT 串口把继电器口抢了）：

- 继电器在启动时打开失败（口被别的程序占着等），`relay.port` 会是空的；这时 DUT
  串口自动识别只排除「已配置的继电器口」，等于没排除——它会把唯一的 CH340 抢走，
  继电器此后一直 `PermissionError`，界面上就是「继电器识别不到」。
- 现在 DUT 口识别会把**继电器自动识别的首选口也预留出来**（继电器没打开也留），
  拿不到调试口时给出明确原因：`没有可用的调试串口（COM8 留给继电器…）`。
- 第二个 CH340 / Prolific 等照样能当 DUT 口，不受影响。要强行用同一个口当 DUT 口，
  就在设置里显式填端口（显式配置不走自动识别）。

v1.0.8 — 设置页串口修复（保存即生效）：

- **修掉「串口改不了」**：设置面板打开期间，每次快照（约 1 秒一次）都会
  `fillSettings()` 回填表单，用户正在输入的端口下一秒就被服务端旧值覆盖。
  现在只在打开面板时填一次。
- **修掉「改了不生效」**：改继电器串口以前只改 `relay.port` 属性，`Serial` 句柄
  还绑在旧 COM 上，写指令照样发到老端口。新增 `RelayController.reconfigure()`：
  先 `close()` 再按新端口 `open()`，保存即重连。
- **串口改成可下拉**：设置页的继电器串口 / DUT 串口接上 `<datalist>`，列出本机
  枚举到的串口和描述（如 `COM8 · USB-SERIAL CH340`），仍可手工输入未枚举的端口。
- 切到「干跑」时会关闭已打开的串口，不再占 COM。
- 保存后的 toast 显示继电器实际重连结果（失败时是警告色，设置仍已落盘）。

v1.0.7 — 共通化适配（换机器 / 新 clone 直接能跑）：

- **补回缺失的 `can_pack.py`**：`can_engine.py` 一 import 就报 `ModuleNotFoundError`，
  CAN 在**任何**机器上都起不来。已随包入库。
- **`zlgcan` SDK 随包入库**：`sdk/zlgcan/`（ctypes 绑定 + `zlgcan.dll` + `kerneldlls`），
  不用再单独下 ZLG 的 Python 包；`find_sdk_dir()` 先找项目内的 `sdk/zlgcan`。
- **32 位解释器自动识别**：`can.python` 留空即可——依次试 `py -3.8-32`、本机
  `Python3*-32` 与 ZCANPRO 自带的 `python38`、PATH 上的 `python`，按子进程 hello
  回报的位数筛掉 64 位；也可用环境变量 `CBSTUDIO_PYTHON` 强制指定。
- **报文清单路径按工作台目录解析**：`can.manifest` 改成相对路径
  `can_matrix_manifest.json`，不再依赖同事机器上的 `F:\…` 绝对路径；清单缺失时
  直接报「报文清单不存在: <解析后的绝对路径>」。
- **默认值不再写死别人的路径**：`relay.port` / `probes.serial.port` / `probes.adb.exe`
  默认留空走自动识别；adb 探测增加随包 `platform-tools/` 与
  `ANDROID_HOME` / `ANDROID_SDK_ROOT` / `%LOCALAPPDATA%\Android\Sdk`。
- 新增 `requirements.txt`（`pyserial` 必需、`openpyxl` 仅重建清单时需要），
  `使用说明.md` 可以直接照做。
